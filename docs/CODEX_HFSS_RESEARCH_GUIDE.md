# 使用 Codex 构建 HFSS 自动化科研工作流

本文面向已经使用 Ansys HFSS、希望借助 Codex 将重复仿真工作转化为可追踪计算实验的研究人员。重点是通用方法、接口边界与扩展方式。仓库中的 diplexer 项目仅作为已验证案例。

## 1. 系统边界

### 1.1 HFSS 的职责

HFSS 负责：

- 三维电磁模型与材料定义；
- 边界条件、激励和端口；
- 网格自适应与数值求解；
- S 参数、场分布、损耗和收敛数据的生成。

### 1.2 Codex 的职责

Codex 负责：

- 阅读已有工程、脚本和实验记录；
- 识别可参数化变量及其依赖；
- 编写单次运行和批量实验脚本；
- 调用 HFSS 批处理接口；
- 整理参数、日志、结果和失败信息；
- 编写后处理程序；
- 根据结果生成下一轮实验建议；
- 维护可复现文档。

### 1.3 研究者的职责

研究者必须决定：

- 科学问题是否值得研究；
- 哪些几何量具有明确物理含义；
- 哪些变量允许变化、哪些必须固定；
- 指标定义和可接受阈值；
- 仿真结果能够支持多强的结论；
- 是否需要容差、测量或其他模型进行验证。

Codex 可以加速执行和审计，不能代替电磁理论判断。

## 2. 通用闭环

```text
研究目标与约束
        ↓
参数化 HFSS 基准模型
        ↓
Codex 审计变量、Setup、端口和导出路径
        ↓
生成单次运行脚本并完成 smoke test
        ↓
生成 DOE / 参数扫描 / 优化候选
        ↓
HFSS 非图形批处理求解
        ↓
Touchstone、场数据、日志、profile、convergence
        ↓
Python 计算完整频段指标
        ↓
Codex 汇总趋势、异常和下一轮假设
        ↓
研究者审查物理合理性并决定后续实验
```

这里的核心产物不是某个“最优参数”，而是一条可追溯证据链：

```text
科学假设 → 参数方案 → HFSS case → 原始结果 → 指标 → 结论
```

## 3. 三层架构

为保证复用性，应把系统拆成三层。

### 3.1 通用核心层

与器件类型无关：

- HFSS 安装与启动；
- AEDT 项目打开、复制和保存；
- 变量读取与修改；
- Design、Setup、Sweep 选择；
- 非图形求解；
- 网络参数、场数据和收敛信息导出；
- 独立运行目录；
- 日志、状态、重试和并行控制；
- manifest 与结果索引。

### 3.2 器件适配层

由具体项目决定：

- 变量名和单位；
- 几何约束及变量联动；
- 端口数量和端口含义；
- 扫频范围；
- 后处理指标；
- 合格阈值；
- 禁止进入的几何区域。

### 3.3 研究策略层

由研究问题决定：

- 单因素扫描；
- 全因子或部分因子 DOE；
- 局部细化；
- 灵敏度分析；
- 代理模型或贝叶斯优化；
- 鲁棒设计和制造容差；
- 何时停止参数搜索并修改拓扑。

把这三层混在单个脚本中，短期可运行，长期难以迁移和复核。

## 4. 当前仓库已经验证的能力

当前实现已打通以下链路：

1. 读取和修改文本形式的 `.aedt` 项目变量；
2. 生成独立的参数化项目副本；
3. 通过 HFSS 2021 IronPython 以 NonGraphical 模式运行；
4. 调用 `AnalyzeAll()`；
5. 导出 Touchstone、profile 和 convergence；
6. 解析三端口 S 参数；
7. 计算交叉频率、特定频点抑制、波纹、插损和回波损耗；
8. 生成 JSON、SVG 和交互式 HTML；
9. 使用 UID、manifest 和独立目录管理批量实验；
10. 使用有限并行度执行多个 HFSS case；
11. 记录多轮参数实验的动机、结果和下一轮假设。

这些能力证明 Codex 可以围绕 HFSS 建立端到端科研闭环。当前部分路径、Design、Setup 和指标仍与案例耦合，因此仓库属于可运行原型，尚未形成配置驱动的通用软件包。

## 5. 从零建立最小闭环

### 步骤 1：冻结可手动求解的基准模型

基准 `.aedt` 应满足：

- 在 HFSS GUI 中能够正常打开和求解；
- 端口、材料、边界和 Setup 已确认；
- 关键几何量已经参数化；
- 基准结果与研究者预期一致；
- 原文件只读保存，不作为脚本输出目标。

### 步骤 2：识别工程元数据

至少记录：

```yaml
hfss:
  version: "2021.2"
  executable_or_root: "<local installation path>"

project:
  file: "model.aedt"
  design: "HFSSDesign1"
  setup: "Setup1"
  sweep: "Sweep"
  ports: 3
```

实际通用实现应从配置读取这些字段，避免写死在 Python 文件中。

### 步骤 3：审计变量

对每个候选变量记录：

```yaml
parameters:
  line_length:
    unit: mm
    baseline: 1.20
    allowed_range: [1.00, 1.40]
    physical_role: "controls electrical length"
    dependencies:
      - substrate_length
    risks:
      - "port may detach below 0.95 mm"
```

变量审计需要回答：

- 变量是否真实存在；
- 它是数值还是表达式；
- 单位是否一致；
- 修改后哪些对象会移动；
- 端口、空气盒和边界是否同步；
- 哪些参数组合会产生非法几何。

### 步骤 4：完成一次基准批处理

第一次自动运行不修改任何参数，只验证：

- HFSS 能被无界面启动；
- 工程能够打开；
- Design 和 Setup 能正确定位；
- 求解完成；
- 导出文件存在；
- 导出结果与 GUI 基准一致；
- HFSS 能正常关闭。

### 步骤 5：完成一个参数变更 smoke test

只修改一个变量，幅度应足以让曲线发生可辨识变化，同时不应破坏几何。验证：

- 新 `.aedt` 中变量确实改变；
- 其他变量未被意外改写；
- 输出结果变化方向符合基本物理预期；
- case 目录包含完整记录。

### 步骤 6：定义指标

指标必须包含频率区间、端口含义和数学定义。例如：

```yaml
metrics:
  return_loss:
    trace: S11
    band_GHz: [20, 30]
    statistic: max_dB
    target: "<= -10 dB"

  insertion_loss:
    trace: S21
    band_GHz: [20, 30]
    statistic: min_dB

  ripple:
    trace: S21
    band_GHz: [20, 30]
    statistic: peak_to_peak_dB
```

波纹和最差回波损耗应在完整频率数组上计算。仅抽取若干整数频点可能漏掉窄峰。

### 步骤 7：生成批量实验

每个 case 建议采用以下结构：

```text
runs/
└── 000123_case_name/
    ├── source.json
    ├── parameters.json
    ├── project.aedt
    ├── result.sNp
    ├── convergence.conv
    ├── profile.prof
    ├── metrics.json
    ├── run.log
    └── status.json
```

批次根目录保存 `manifest.json` 或表格，至少包括 UID、参数、路径、状态、指标和错误摘要。

## 6. 如何让 Codex 接管已有项目

### 6.1 第一轮只做审计

可直接给 Codex：

> 阅读当前仓库和 HFSS 自动化脚本。先不要修改文件。请识别 HFSS 安装路径、基准 AEDT、Design、Setup、Sweep、端口数、变量修改方式、输出文件、指标函数和批量实验目录。区分通用逻辑与器件专用逻辑，并列出可能导致错误结果的隐含假设。

### 6.2 生成最小运行方案

> 基于审计结果，设计一个不覆盖原始 AEDT 的最小批处理 smoke test。先运行基准模型，再只修改一个安全参数。每个 case 使用独立目录，保存参数、日志、Touchstone、profile 和 convergence。运行前列出将要执行的命令和验收标准。

### 6.3 设计参数实验

> 研究目标为【填写目标】。候选变量为【填写变量】，固定条件为【填写条件】。先根据物理作用提出参数优先级和预期变化方向，再设计最小规模的分阶段 DOE。不要直接生成大规模网格。每一轮必须说明假设、参数范围、停止条件和下一轮决策规则。

### 6.4 分析失败 case

> 检查本批次所有失败 case。按项目打开失败、几何非法、网格失败、求解失败、导出失败、结果解析失败分类。保留失败记录，不要直接重跑。先判断失败是否与特定参数区域相关，再提出最小修复方案。

### 6.5 汇总结果

> 从 manifest 和每个 case 的 metrics.json 汇总本轮实验。检查指标定义是否一致，识别 Pareto 候选、异常曲线和参数敏感度。所有结论都引用 UID。不要把采样范围内最佳结果表述为全局最优。

### 6.6 设计下一轮

> 根据本轮结果提出下一轮实验。每个新增 case 必须对应一个明确假设。优先缩小不确定性或区分替代解释，避免只围绕当前最佳点机械加密。

## 7. 迁移到其他 HFSS 任务

### 7.1 天线

替换或增加：

- S11 带宽；
- 增益与实现增益；
- 辐射效率；
- 主瓣方向；
- 半功率波束宽度；
- 交叉极化；
- 方向图导出与角域指标。

### 7.2 滤波器和双工器

常用指标：

- 通带插损；
- 回波损耗；
- 3 dB 带宽；
- 带内波纹；
- 阻带抑制；
- 传输零点；
- 群时延；
- 多端口隔离度。

### 7.3 功分器、耦合器与巴伦

常用指标：

- 分配幅度；
- 相位差；
- 隔离度；
- 输入输出匹配；
- 幅相不平衡。

### 7.4 封装、互连与信号完整性

常用指标：

- 插损与回损；
- 近端和远端串扰；
- 模态转换；
- 阻抗；
- 眼图或时域反射结果；
- 材料和工艺容差。

迁移时通常不需要重写 HFSS 启动和实验管理层，只需替换器件适配层与结果插件。

## 8. 参数搜索策略

### 8.1 单因素扫描

适合：

- 验证参数作用方向；
- 检查单调性；
- 发现非法区间；
- 粗略估计灵敏度。

局限：无法识别参数交互。

### 8.2 二维或低维 DOE

适合检查两个关键参数之间的耦合。参数范围应基于前一轮结果和物理约束，避免无依据的全空间扫描。

### 8.3 局部细化

只能说明在当前邻域和当前离散网格中的表现。需要报告网格步长、搜索边界和停止条件。

### 8.4 代理模型和贝叶斯优化

适合单次仿真成本高、变量数量适中的问题。引入前应保证：

- 输入参数定义稳定；
- 指标计算一致；
- 失败样本被正确处理；
- 初始样本覆盖合理；
- 不确定性被保存；
- 最终候选由 HFSS 重新验证。

### 8.5 鲁棒设计

最终设计不能只在标称参数下优秀。应对加工尺寸、材料参数、铜厚、表面粗糙度、装配偏差等进行容差分析。

## 9. 结果可信性检查

每个最终候选至少检查：

1. 自适应网格是否收敛；
2. 不同网格或收敛阈值下结果是否稳定；
3. 扫频插值是否掩盖窄峰；
4. 端口模式和参考面是否正确；
5. 材料损耗和导体模型是否符合目标频率；
6. 边界距离是否充分；
7. 参数变化是否导致几何穿透、悬空或端口脱离；
8. 指标是否在完整区间计算；
9. 是否存在同样合理的替代解释；
10. 是否需要电路模型、另一求解器或实测交叉验证。

## 10. 数据与版本管理

建议保留：

- 基准 AEDT；
- 最终候选 AEDT；
- 最终候选的原始导出数据；
- 参数和指标 JSON；
- manifest；
- convergence/profile 摘要；
- 生成图表的脚本；
- HFSS 版本和环境配置；
- 研究日志。

通常不提交：

- 可重新生成的 `.aedtresults`；
- 网格和求解缓存；
- 大量中间 AEDT 副本；
- 临时图像和锁文件。

大型结果可放在外部对象存储，并在仓库中保存校验和及索引。

## 11. 当前实现的主要边界

当前仓库仍存在以下通用化缺口：

- Windows 和 HFSS 安装路径写在脚本中；
- Design、Setup、Sweep 和端口数部分写死；
- `.aedt` 文本修改依赖具体 AEDT 格式；
- 多个 sweep 脚本重复实现 Touchstone 和指标逻辑；
- 指标定义与 diplexer 案例耦合；
- convergence 已导出，但尚未形成统一自动验收；
- 缺少通用 YAML 配置、插件接口和测试。

因此当前正确定位是：

> 已验证可运行的 Codex–HFSS 自动化科研原型，能够证明端到端方法，并为配置化、模块化平台提供基础。

## 13. 最小交付标准

将该流程用于新的 HFSS 科研项目时，至少应交付：

- 一个冻结的基准模型；
- 一个可重复的基准批处理命令；
- 一个参数变更 smoke test；
- 一份参数和几何约束表；
- 一个机器可读 manifest；
- 一套明确的指标定义；
- 一份失败 case 记录；
- 一个最终候选及其收敛证据；
- 一份从假设到结论的实验日志；
- 一份说明结果适用范围和未验证部分的报告。
